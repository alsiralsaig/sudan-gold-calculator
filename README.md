# حاسبة الذهب والشركاء — Sudan Gold Calculator

تطبيق ويب (PWA) لتجار الذهب في السودان: تسجيل المشتريات والمبيعات والديون، حساب الأرباح وتوزيعها على الشركاء، ومتابعة أسعار الذهب والعملات لحظياً.

---

## القاعدة الأساسية: العيار 21 هو العيار الرسمي

**كل التسعير في التطبيق يُبنى على سعر جرام عيار 21 (نقاوة 875).**

- سعر جرام 21 هو السعر المرجعي للبيع والشراء.
- باقي العيارات تُشتق منه بنسبة النقاوة: `سعر العيار = سعر 21 × (نقاوة العيار ÷ 875)`.
- أي وزن بعيار آخر يُحوَّل إلى **معادل عيار 21** قبل جمعه أو تقييمه، حتى تكون المقارنة عادلة:
  - 100 جرام عيار 18 = **85.71 جرام معادل 21**
  - 100 جرام عيار 24 = **114.29 جرام معادل 21**
- وحدة الوزن السودانية محفوظة كما هي: **1 جرام = 4 حبات = 40 جزء** (تُخزَّن داخلياً كـ 100 وحدة).

معادلات التسعير:

```
سعر الجرام (عيار 21) = (سعر الأونصة عالمياً ÷ 31.1034768) × (21 ÷ 24) × سعر صرف الدولار
القيمة = (معادل عيار 21 بالجرام) × سعر جرام 21
```

## المعالجات التي تمت على النسخة السابقة

### 1. دقة الأسعار الحية (إصلاح جوهري)

| المشكلة | الإصلاح |
| --- | --- |
| نمط البحث عن سعر السوق الموازي لا يطابق بنية المقال → التطبيق يرجع **بصمت** إلى رقم ثابت `8400` | قارئ جديد (`src/lib/rates.ts`) يقرأ جدول «السوق الأسود» المنشور فعلياً (سعر الشراء والبيع) |
| سعر الريال/الدرهم/الجنيه المصري يُحسب بمعادلة ثابتة (÷3.75، ÷3.6725، ÷48.5) | تُقرأ من الجدول المنشور، ومتى لم تُنشر يُعلن التطبيق ذلك بدل أن يخترع رقماً |
| حدود قديمة `5000–15000` ترفض أي سعر خارجها | حدود منطقية واسعة مع تحقق (سعر البيع ≥ سعر الشراء) |
| لا يوجد مؤشر لمصدر السعر أو وقت تحديثه | بطاقة أسعار تعرض: المصدر، وقت الجلب، حالة التحديث، والتحذيرات |
| فشل الجلب يستبدل الأسعار بصمت | حفظ «آخر قيمة صحيحة» + وسمها بوضوح كغير محدّثة |
| لا يمكن ضبط فرق سوق المدينة | تعديل سوق محلي (٪) + خيار تثبيت السعر يدوياً |
| — | إضافة سعر الدولار الرسمي في البنوك للمقارنة |

### 2. دقة الحسابات المحاسبية

- **المخزون**: يُحسب لكل عيار على حدة، مع تحويل إلى معادل عيار 21 (سابقاً: جمع الأوزان كما هي دون تعديل النقاء).
- **تقييم المخزون** بسعر عيار 21، مع **تكلفة المخزون** و**ربح غير محقّق** تقديري ومتوسط تكلفة الجرام.
- **كشف عجز العيارات**: تنبيه إذا بعت من عيار أكثر مما اشتريت.
- **الذمم المدينة (البيع الآجل)**: حقول مدفوع/متبقي + سجل تحصيل على كل فاتورة.
- **توحيد المعالجة**: السجلات المؤرشفة تُستثنى من الأرباح والمخزون (سابقاً كانت تُستثنى من المخزون فقط).
- حاسبة العيارات الموحّدة (`src/core/purity.ts`) بدل تكرار المعادلات في كل شاشة.

### 3. استقرار البيانات والمزامنة

- **سجل حذف (Tombstones)**: السجل المحذوف لا يعود من السحابة عند المزامنة (كانت أكبر مشكلة خطر فقدان/رجوع بيانات).
- **دمج بالأحدث تعديلاً** مع احترام سجل الحذف، وإحياء السجل إذا عُدّل بعد حذفه.
- **مزامنة تلقائية** بعد أي تعديل (بتأخير 4 ثوانٍ) + مزامنة عند فتح الشاشة.
- **معرّفات فريدة** (`crypto.randomUUID`) بدل `Date.now()` التي قد تتصادم.
- **ترحيل تلقائي** لبيانات الإصدارات السابقة (`v4`/`v5` → `v6`) مع تنظيف بيانات الحساب التجريبي القديم.
- **نسخ احتياطي JSON** يضم سجل الحذف، و**تصدير CSV** لكل الحركات (يفتح في Excel بالعربي).

### 4. الأمان

- **تجزئة رمز القفل PIN** بـ SHA-256 مع ملح بدل تخزينه كنص صريح، مع ترقية تلقائية للرمز القديم.
- **تأخير متزايد** بعد المحاولات الفاشلة (في الواجهة وفي الخادم).
- **حد لمحاولات تسجيل الدخول** (8 محاولات / 15 دقيقة لكل IP+بريد) مع إرجاع 429.
- **إلزام `AUTH_SECRET`** في الإنتاج بدل المفتاح الافتراضي `change-me-in-vercel`.
- جلسة بتوقيع HMAC + انتهاء صلاحية 30 يوماً، وكوكي `httpOnly` و`sameSite=lax`.

### 5. ميزات جديدة

- **شاشة التقارير والكشوفات**: تقرير يومي/أسبوعي/شهري، حركة الأوزان، التحصيل والذمم، جرد المخزون، أنصبة الشركاء، أعلى الزبائن والموردين، **كشف حساب زبون أو مورد**، طباعة/PDF و تصدير Excel.
- **البيع الآجل** بكل تفاصيله (مدفوع/متبقي/سجل دفعات) مع زر تحصيل سريع من الجدول.
- **حماية من السداد الزائد** في المشتريات.
- **مؤشر أثر الوزن** بمعادل عيار 21 أثناء إدخال أي عملية.
- **رأس المال والذمم** في لوحة التحكم بشكل مترابط وقابل للنقر.
- **أنماط طباعة** مخصّصة للكشوفات (خلفية بيضاء وأرقام واضحة).

### 6. هندسة المشروع

- فصل منطق العمل عن الواجهة: `src/core/purity.ts`، `src/core/accounting.ts`، `src/core/merge.ts`، `src/lib/rates.ts`.

## التشغيل محلياً

```bash
npm install
cp .env.example .env.local   # املأ القيم (المزامنة تحتاجها فقط)
npm run dev                  # http://localhost:3001
```

الأوامر:

```bash
npm run typecheck   # فحص الأنواع
npm test            # الاختبارات
npm run check       # الاثنان معاً
npm run build       # بناء الإنتاج
```

> التطبيق يعمل بدون Supabase (تخزين محلي في المتصفح). Supabase مطلوب فقط للمزامنة بين الأجهزة وتسجيل الدخول.

---

## إعداد Supabase (للمزامنة السحابية)

1. أنشئ مشروعاً على [supabase.com](https://supabase.com).
2. نفّذ ملف `supabase-schema.sql` من SQL Editor.
3. أضف إلى متغيرات البيئة (محلياً في `.env.local` وعلى Vercel):
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `AUTH_SECRET` (16 حرفاً على الأقل — `openssl rand -hex 32`)

---

## النشر على Vercel

1. اربط المستودع بـ Vercel.
2. أضف متغيرات البيئة الثلاثة أعلاه في Project Settings → Environment Variables.
3. Deploy. ملفات `manifest.json` و`sw.js` معدّة للعمل كتطبيق PWA على الجوال.

## ملاحظات وفروقات مقصودة

- **الأسعار لحظية قدر الإمكان** لكن المصادر صحفية (تُحدَّث مرة أو أكثر يومياً)، لذلك يعرض التطبيق دائماً وقت الجلب ويسمح بالتعديل اليدوي أو بتثبيت السعر.
- **المصادر**: Yahoo Finance / Gold-API / Coinbase للأونصة، و«اخبار السودان» (السوق الموازي + البنوك) و«سودافاكس» كبديل للدولار والعملات. المنطق الموحّد في `src/lib/rates.ts` ويسهل إضافة مصدر جديد.
- **الربح غير المحقّق** تقديري بناءً على التكلفة المسجّلة وسعر السوق الحالي، وليس ربحاً محصّلاً.
- **تجزئة PIN في المتصفح** تحمي من الاطّلاع المباشر على الرمز، وليست بديلاً عن قفل الجهاز نفسه؛ بيانات السجلات نفسها تبقى محلية/سحابية حسب إعداداتك.
